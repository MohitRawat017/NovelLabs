# Repository Structure Guide

This guide defines the current working structure of the repository and what is safe to clean.

## Goals

- Keep runtime paths stable (no breaking import/path changes).
- Separate production-critical code from local pipeline and generated data.
- Make cleanup decisions explicit.

## Canonical Structure

```text
audioBook/
├── src/
│   ├── api/                    # FastAPI backend (production + local)
│   │   ├── routes/
│   │   ├── services/
│   │   ├── storage/            # Canonical R2 integration
│   │   └── legacy/             # Backward-compatible legacy modules
│   ├── SCRAPER/                # Active scraper package used by adapter
│   ├── scraper.py              # Local CLI scraping flow
│   └── segmenter.py            # Local CLI segmentation flow
├── web/                        # React frontend (Vite)
├── scripts/                    # Operational scripts (upload/cleanup)
├── data/                       # Local DB + scraped text outputs
├── audio/                      # Local generated audio/timing outputs
├── logs/                       # Runtime logs
├── docs/                       # Project documentation and structure map
├── requirements.txt            # Full local/dev dependencies
├── requirements-prod.txt       # Lean production dependencies
└── Dockerfile                  # Production container entrypoint
```

## Working Status Matrix

### Production-critical (do not move)

- `src/api/**`
- `web/**`
- `requirements-prod.txt`
- `Dockerfile`

### Local pipeline (active, optional for deployed backend)

- `src/SCRAPER/**`
- `src/scraper.py`
- `src/segmenter.py`
- `scripts/upload_novels_to_r2.py`

### Generated/runtime outputs (safe to clear if you understand consequences)

- `audio/**` (regenerated by TTS)
- `logs/**` (runtime logs)
- `data/output/**` (scraped chapter text)
- `data/smoke-scraper/output/**` (smoke run output)
- `tests/tmp*` (temporary test artifacts)

### Legacy compatibility area

- `src/api/legacy/**`

These files are kept only for backward compatibility and should not be used for new development.

## Safe Cleanup Commands (optional)

Use these only if you want to reclaim space and you do not need the local generated artifacts.

```powershell
Remove-Item -Recurse -Force .\logs\backend\* -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .\data\smoke-scraper\output\* -ErrorAction SilentlyContinue
```

Do not blindly delete `audio/` or `data/output/` unless you are sure you can regenerate them.

## Rules for Future Changes

- New production backend modules go under `src/api/`.
- New frontend modules go under `web/src/`.
- New one-off scripts go under `scripts/`.
- Any module replaced for compatibility should move to `src/api/legacy/` with a shim at the old path.
- Avoid introducing new top-level folders unless they are cross-cutting (`docs`, `scripts`, `web`, `src`).
